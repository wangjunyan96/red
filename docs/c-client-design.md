# C 端「网页下单」设计说明

面向用户（toC），与后台 `/` 分开。后台给运营管 Token/任务，C 端给用户下单、充值、查单。

参考图是「聊天下单 + 项目中心」；本设计**复用同一套交互**，视觉改成浅色青绿消费风（不用参考图的紫气泡，也不用后台暗红）。

---

## 1. 产品对照

| 参考图 | 本系统含义 |
| --- | --- |
| 聊天下单 | 用户发重逢码/口令，系统匹配项目、扣余额、生成云手机任务 |
| 项目中心 | 可售项目列表（当前：英雄杀-结义，后续可加） |
| 关键词 | 点选后填入输入框，便于匹配项目 |
| 充值 / 卡密 | 用卡密给 `t_user.points` 加余额（单位：分） |
| 订单 | 当前用户的下单记录，状态跟云手机任务走 |
| 余额 | `points / 100` 元 |

主流程：登录 → 选项目或发口令 → 扣款 → 写入 `t_task`（从 Token 库取号）→ 云手机脚本领取执行。

---

## 2. 信息架构

```
/c/                         C 端入口（与 / 后台隔离）
├── 登录 / 注册
├── 聊天下单（默认）
├── 项目中心
├── 关键词（底部弹层）
├── 充值（弹层）
├── 卡密兑换（弹层）
└── 订单列表（弹层）
```

不新开路由站点，单页切换，方便手机。

---

## 3. 页面与功能

### 3.1 顶栏
品牌、在线状态、头像字母、等级「普通」、余额、退出。

### 3.2 聊天下单
- 欢迎语 + 余额卡片
- 用户气泡 / 系统气泡 / 「下单成功」卡片（项目、单号、邀请码、扣款、余额、时间、处理中）
- 输入框发送；识别：
  - `[口令]` 或独立一行的重逢码
  - 文案里的关键词（结义/重逢/英雄杀）匹配项目
  - 可先在项目中心选定「当前项目」
- 失败回系统消息：无码、余额不足、未接单、Token 库存不足

### 3.3 项目中心
卡片：名称、零售价、分类、接单中/未开放、教程。点卡片设为当前项目并回到聊天。

### 3.4 关键词 / 充值 / 卡密 / 订单
底部四入口，手机为底栏，桌面为顶栏旁按钮 + 右侧抽屉。

## 4. 响应式

| 宽度 | 策略 |
| --- | --- |
| ≤ 767px | 单列手机布局，底栏 + 顶 Tab |
| 768–1023px | 单列加宽，最大 560px 居中 |
| ≥ 1024px | 居中壳层最大 1180px：左聊天、右项目列表常驻；底栏改到顶栏 |

覆盖常见手机 375/390/414 与桌面 1280/1366/1440/1920。使用 `dvh` + `safe-area-inset`。

## 6. 数据

- `t_c_project`：可售项目（绑定 `game_code` + `task_type`，价格分）
- `t_c_keyword`：关键词 → 项目
- `t_c_order`：用户订单（`order_no`、金额、邀请码、`task_id`）
- `t_c_message`：聊天记录
- `t_c_card`：卡密
- 余额仍用 `t_user.points`（分）

下单成功：扣分 + `TaskService.addTasks` + 写订单。删未完成后台任务时 Token 仍会退回未关联。

---

## 7. C 端接口（`/api/v1/c`）

- `GET /me?userId=` 刷新用户
- `GET /projects` `GET /keywords`
- `POST /chat` `{ userId, text, projectId? }`
- `GET /orders?userId=`
- `POST /cards/redeem` `{ userId, cardKey }`
- 登录注册沿用 `/api/v1/users/login|register`

首期无支付渠道，充值只走卡密。

---

## 8. 安全（首期）

与现有后台一样，前端带 `userId`（localStorage）。后续再上登录态 Token。
